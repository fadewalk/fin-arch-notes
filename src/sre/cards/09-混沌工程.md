## 一句话定位
系统正确性无法被理论或实践穷尽证明,只能转为统计置信度;混沌工程主动制造故障提高发现问题概率,对象含硬件、监控、运维与值班人员。

## 典型故障模式
- **SLI 监控缺位就开实验**:软件不可见只能靠指标间接了解行为 → 实验做完无数据可分析;补齐 SLI 覆盖是前置条件。
- **伤害半径失控**:跳过测试/回归/预生产直接生产全量 → 一次"演练"变真事故;必须逐级升级到生产灰度、半径尽量小。
- **断言式实验**:用测试思维(已知正确答案)做混沌 → 真正暴露的未知问题被漏掉;应用假设,接受未知结果。
- **对象边界低估**:只扰动应用进程,不覆盖硬件/操作系统/虚拟机/系统 API 各层 → 未实验的层次真实爆发;分层找自变量。
- **证明幻觉**:以为"Raft 广泛使用=被证明正确" → 形式化证明只适用有限状态,Raft 状态无限;正确性只能靠实验抬置信度。

## 观测信号
- `sli_coverage_ratio`:SLI(吞吐/延时/性能)的监控覆盖率;低于 100% 先补监控再实验。
- `blast_radius_percent`:实验影响范围(用户/节点比例);从灰度小规模按环境层级放大。
- `injected_vs_detected_faults`:注入扰动数 vs 被告警捕获数;差值即系统盲区清单。
- `slo_breach_during_experiment`:实验期 SLO 违反次数;SLO 是假设的目标值,违反即证伪、转修复。
- `jepsen_invariant_violations`:Jepsen 类正确性验证的违反项;它把 SLO 定义在正确性(目标 100%)上。

## 应急动作
- 实验引发真故障 → 立即回滚扰动源,控制伤害半径,再按正常故障处置。
- 实验暴露问题 → 像修测试 bug 一样建单修复并回归;修复前不在该层重复同强度实验。
- 发现盲区 → 补齐对应 SLI 监控与告警后再做下一轮,监控覆盖是实验前提。
- 实验通过 → 记录为置信度证据;未发现问题只提升信心,不是保证。

## 常见误区
- 不是"故意搞坏生产环境":是通过制造问题理解系统能力边界,伤害半径必须尽量小。
- 别用断言思维:先提出自变量-因变量假设、接受未知结果,这是与测试的本质区别。
- SLA/SLO/SLI 极易混:SLI 是"看什么"(实验因变量),SLO 是"达到多少"(实验假设),SLA 是包含两者的协议;系统边界含人与运维,勿低估。
